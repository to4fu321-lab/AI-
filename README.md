## 動画修復アプリ（`/repair`）

撮影の中断や転送の失敗で再生できなくなった MP4 / MOV を、ブラウザだけで修復するページです。iPhone の Safari から使えます（ホーム画面に追加可能）。

まずファイルを診断して壊れ方を特定し、それに合った方法で修復します。動画はアップロードされず、再エンコードもしません（元ファイルのデータに新しい索引を付け直すだけなので、数 GB のファイルでも扱えます）。

| 壊れ方 | 修復方法 |
| --- | --- |
| 索引（`moov`）がない（録画・保存の中断） | 生データから映像・音声フレームを検出して索引を作り直す |
| 途中で切れている（ダウンロード・コピーの中断） | 残っている索引を使い、実在するサンプルだけで作り直す |
| 一部がゼロやゴミで上書きされている | 壊れたフレームと、それに依存するフレームを次のキーフレームまで除去。時間軸は保つ |
| 先頭（ヘッダ）が壊れている | ファイル内から `moov` を探し出して利用する |
| データ位置がずれている（先頭側のバイト欠落） | ずれ量を割り出して索引を補正する |
| 索引が壊れている | 残った設定情報を使い、生データから作り直す |
| MP4・MOV ではない／中身がすべてゼロ | 修復できない理由を表示する |

索引が残っている場合は映像・音声の形式を問いません（PCM 音声なども可）。索引がない場合の対象は H.264 / HEVC の映像と AAC 音声で、次のどちらかで再生設定を得ます。

- **参考動画あり**: 同じカメラ・同じ設定で撮った正常な動画から再生設定を引き継ぎます（H.264 / HEVC）。
- **参考動画なし**: 映像に再生設定が埋め込まれていればそれを使います。H.264 で埋め込まれていない場合は、スライスヘッダの解析と試行デコード（ffmpeg の WebAssembly 版）で再生設定を割り出します。

仕組みの本体は `src/lib/repair/` にあります。

| ファイル | 役割 |
| --- | --- |
| `scan.ts` | 生データから映像フレーム（NAL）と音声フレーム（AAC）を検出 |
| `aac.ts` | AAC のビットストリーム構文を追ってフレーム境界を特定 |
| `h264.ts` / `hevc.ts` | SPS / PPS / スライスヘッダの解析と生成 |
| `estimate.ts` | 参考動画なしの場合の SPS / PPS 推定 |
| `indexRepair.ts` | 索引が残っているファイルの検証と修復 |
| `mp4.ts` | `moov` の読み取り・探索と、新しい `moov` の書き出し |

コマンドラインからも試せます（システムの `ffmpeg` が必要）。

```bash
npx tsx scripts/repair-cli.ts 壊れた動画.mp4 出力.mp4 [参考動画.mp4]
```

参考動画が必要な場合（索引も埋め込み設定もない HEVC）は、壊れた動画のデータからフレームレートと解像度を推定し、どの設定で参考動画を撮ればよいかを表示します。参考動画を指定したときは、その設定で先頭のフレームを試しにデコードし、設定が合っていない可能性があれば警告します。

### 既知の制限

- 索引がない HEVC は、映像の中に再生設定（VPS/SPS/PPS）が埋め込まれていれば参考動画なしで修復できます（多くのカメラ・ドライブレコーダー）。iPhone のカメラで撮った動画は、Apple のエンコーダ設定（`appleHevc.ts`）から再生設定を組み立て、解像度と SDR/HDR を試行デコードで判定します。それ以外で埋め込まれていない場合は参考動画が必要です。
- iPhone の動画は、メタデータに残る撮影時の向き（video-orientation）から回転を復元します。
- フレームの途中から壊れている場合、その 1 フレームは検出できず、次のキーフレームまで映像が乱れることがあります。
- 索引がなくデータに穴がある場合、穴の長さはデータ量からの推定です。
- 索引がない場合、AAC 以外の音声（PCM など）は復元されず、映像のみになります。
- 参考動画なしの場合、x264 以外のエンコーダで `pic_init_qp` が 26 以外の動画は色や明るさが崩れることがあります（参考動画を指定すれば解決します）。
- 可変フレームレートの動画は一定のフレームレートとして書き出されます。

## サムネ収集アプリ（`/thumbs`）

URL を入れると、そのページ（と下の階層のページ）にある画像・動画を集めてサムネイルの一覧にします。続けて別の URL を入れると一覧にどんどん追加されます（改行区切りでまとめて入力も可）。一覧はブラウザ（localStorage）に保存されます。

- **🎬 動画 / 🖼 画像** のバッジで種類がわかります。タップで拡大表示・再生、ダウンロードできます（左右スワイプで前後、下スワイプで閉じる）
- 「下の階層」（最大 20 階層）を選ぶと、入力した URL と同じサイトで、同じ階層より下のページをリンクで辿ります（例: `/gallery/` なら `/gallery/...` のみ）。「別のサイトへのリンクも辿る」をオンにすると、最初からリンク先の別サイトも辿ります。`www.` 付きやスマホ用アドレス（`m.` など）へ転送されても同じサイトとして扱います
- 動画を探しているのに見つからないときは、範囲を自動で広げます：同じサイトの別の場所（一覧 → 詳細ページ）→ 設定より最大 2 階層先 → リンク先の別サイト。範囲の外のページからは動画だけを集めます（動画が 1 本も見つからないまま読むのは 60 ページまで）
- `robots.txt` で禁止されたページは読みません（入力したページ自体は常に読みます）。「robots.txt を守る」を外すと読めます。読まなかった・読めなかった理由は、取得中の行に表示します
- サイトが自動アクセスを断るとき（HTTP 403 など）はブラウザで開き直し、通れたらもらった Cookie で続きを読みます。年齢確認の入口ページは「はい」を押して進みます。`<meta refresh>` などの自動転送、フレーム（`<frame>`）で組んだページにも対応
- 「ページ送り」（最大 50 ページ）を選ぶと、「次へ」・ページ番号・`?page=2`・`/page/3` などの続きのページを、階層を増やさずに辿ります
- 全体のページ数の上限は 1000 ページ。サーバーは 1 回に約 40 秒で区切って途中経過を画面へ返し、画面が送り返して続きを取得します（Vercel の実行時間の制限を超えるため）
- 画面を JavaScript で後から描くサイトは、サーバー上の本物のブラウザ（Chromium）で開いて、表示後の HTML と、ブラウザが受け取った画像・動画の通信から集めます（「ブラウザで開く」：自動／常に／使わない）。ブラウザの通信もすべて内部ネットワーク宛てでないか検査します
- 一覧ページ → 詳細ページ型のサイトでは、サムネイル付き・再生時間付きなど「動画らしい」リンクを先に読み、「一覧 1 ページ目 → その詳細ページ → 一覧 2 ページ目 → …」の順に辿ります。`onclick` や `data-href` で移動するカードも辿ります
- iframe で埋め込まれた外部の動画プレーヤーの中も読みます（2 段まで）。見つけた動画は、そのプレーヤーのページを Referer にして確認・再生・保存します（直リンク禁止対策）
- 動画プレーヤーがあるのに動画が見つからないページは、ブラウザで開いて再生ボタンを押し、読み込まれた動画を記録します。プレーヤーの手がかりがなくても、動画のページらしい（入力したページ・動画らしいリンクから来た・URL や部品の名前に video / player）のに動画が 1 本もないときは、ブラウザで開いて「▶」「再生」などのボタンを押してみます（サイトごとに 3 回まで試し、見つかったサイトは続ける）
- 埋め込み動画は YouTube（押すまで読み込まない lite-youtube なども）・Vimeo・ニコニコ・TikTok・Dailymotion・Instagram のリール・Streamable・bilibili・Facebook を見分けます
- このアプリのサーバーからは断られる動画は、本物のブラウザで動画のあったページを開いてから確かめ直し、見られれば出します（1 回の実行で 10 本まで）。見つけたのに出さなかった動画があるときは、その本数と理由（断られた / ファイルがない）を取得中の行に表示します
- サムネイルのない動画には、一覧ページのリンクのサムネイル → 詳細ページの og:image（サイト共通のロゴらしいものは除く）の順で代わりを付けます。それもなければ、画面側で動画から 1 コマ取り出して作り、端末（IndexedDB）に保存します
- 取得した URL は履歴（最新 50 件）に残り、よく使うサイトは設定ごと ☆ で 5 個まで登録できます（どちらもこの端末のブラウザに保存）
- 拾うもの: `<img>`（`srcset`・遅延読み込みの `data-src` 含む）、`<video>` と `poster`、OGP / Twitter カード画像、JSON-LD の VideoObject、メディアファイルへの直リンク、スクリプト内の動画 URL（読みにくくしたスクリプト・Base64・URL の中の URL・`video_url` などのキー名も）、YouTube / Vimeo の埋め込み
- URL の見た目だけで動画とした候補は、先頭の中身を見て本当に動画か確かめます。サーバーから断られて確かめられなかったものは、`.mp4` などの形なら残します（手元の端末からは再生できることが多いため）
- 同じ動画は 1 個にまとめます（期限・署名だけ違う URL、画質違い、MP4 と HLS の形式違い、別のページで見つけた同じファイル）。URL がまったく違っても、中身の指紋（ファイル全体の大きさ＋先頭 4 KB の要約）が同じなら同じファイルとして 2 個目を出しません。一覧ページのカードの短いプレビュー動画は、詳細ページの本編を出すときは出しません（本編がないときだけ代わりに出す）
- リンク切れは最初から一覧に出しません。サーバーが画像・動画・埋め込み動画（YouTube / Vimeo は公式の窓口に確認）を 1 件ずつ先頭だけ取りに行き、見られると確かめられたものだけを画面へ送ります（404・断られる・サイトがない・中身が違うものは捨て、時間切れは 3 回まで確かめ直す）。確かめきれない分は次の回へ持ち越します。画面に保存した一覧も、確かめてから 6 時間たったもの・確かめていないものは、確かめ直して見られるものだけ表示します
- ダウンロード用の仕組みで配っている動画（`download.php?id=…` のような拡張子のない URL、`application/force-download` などの名乗り、部分取得を断るサーバー、大きさを名乗らないサーバー）も、中身の先頭を見て動画と判断し、正しい種類を名乗り直して再生・サムネイル作成できるようにします。「ダウンロード」と書かれたリンクも先に読みます
- 再生は「元のサイトから直接（このアプリの URL は相手に伝えない＝ブラウザで直接開くのと同じ）→ 駄目ならサーバー経由」の順に自動で試します。配信形式（HLS / `.m3u8`）は iPhone ではそのまま、ほかのブラウザでは hls.js で再生し、サーバー経由のときは目次ファイルの中の URL も中継経由に書き換えます
- 新しく見つけたものほど上に並びます。動画には、サイトが付けた題名（一覧のカードの題名 → 詳細ページの名前）を表示します。
- 動画を取り出せなかったページ（読めない・確認を求められる・動画が見つからない）も、一覧のカードにサムネイルがあれば、サムネイルだけ並べます（タップでそのページを開く）。確認を求められて読まずに並べたページは、読むページ数の上限に数えません。
- Gofile のリンクは、ページのどこに書かれていても拾います（リンク・文中の URL・転送用リンクの中・1 ページ 300 個まで）。X の投稿の URL を入れたとき・ページに X の投稿へのリンクがあるときは、投稿の文にある Gofile のリンクも読みます。「gofile」と書かれたリンク（スレッド・まとめ）は先に辿ります。X の検索結果・プロフィールのページはログインが必要なので読めません。
- 「🔎 ファイル置き場を探す」（Gofile のほか、pixeldrain のファイル・リスト、Google ドライブ、Dropbox、catbox の共有リンクも。文中に書かれただけのリンク・X の投稿の文のリンクも拾う）：キーワード（空でも可）で検索（Yahoo! リアルタイム検索＝X の投稿、Yahoo! の Web 検索、Bing、5ちゃんねるのスレッド検索、はてなブックマーク、Naver、Seznam、Sogou。3 つずつ順に実行）し、結果のページ（X の投稿・掲示板・まとめ）を 2 階層まで辿って、Gofile のリンクの中身だけを集めます。道具・解析系のサイトは辿らず、1 つのサイトからは 12 ページまで。
- 「🔎 動画を探す」：任意のワードで検索（Yahoo! の Web・動画・リアルタイム検索、Bing、はてなブックマーク、5ちゃんねる、Naver）し、結果のサイトを 2 階層まで辿って、見つけた動画を集めます（3 つずつ順に実行）。
- 検索から探す取得は、ひととおり終わった後も「さらに深く探す」（一番下までスクロール、またはボタン）で続けられます。今回は辿らなかったリンク（動画らしくないリンク・1 サイトの上限を超えた分・階層の上限より先）を取っておき、1 回に 80 ページずつ、6 階層先まで読みます。

| ファイル | 役割 |
| --- | --- |
| `src/lib/thumbs/extract.ts` | HTML から画像・動画・リンクを抽出し、種類を判定 |
| `src/lib/thumbs/crawl.ts` | ページを幅優先で辿る（並列 6・ページ送りは同じ階層扱い・時間切れ前に途中経過を返す・動画がなければ範囲を広げる） |
| `src/lib/thumbs/dedupe.ts` | 同じ動画の見分け（画面とサーバーの両方で使う） |
| `src/lib/thumbs/probe.ts` | リンク切れの確認（動画の先頭だけ取りに行く・埋め込み動画の確認） |
| `src/lib/thumbs/sniff.ts` | ファイルの先頭の中身から動画・画像かを見分ける |
| `src/lib/thumbs/render.ts` | サーバー上の Chromium（`@sparticuz/chromium` + `puppeteer-core`）でページを表示して集める。手元では `CHROMIUM_PATH` でブラウザを指定 |
| `src/components/thumbs/videoThumb.ts` | 動画から 1 コマ取り出してサムネイルを作る（直接読めなければサーバー経由）。IndexedDB に保存 |
| `src/lib/thumbs/safeFetch.ts` | 内部ネットワークへの接続を拒否する fetch（SSRF 対策）と、クロール 1 回分の Cookie の入れ物 |
| `src/app/api/thumbs/crawl` | 結果を NDJSON で少しずつ返す（見つかった順に画面に出る） |
| `src/app/api/thumbs/media` | 画像・動画の中継。直リンク禁止の回避（Referer を変えて再挑戦）、Range（シーク）対応、HLS の目次の書き換え、`dl=1` で保存 |

- Gofile（`gofile.io/d/…`）のフォルダは、Gofile の窓口に聞いて中身を集めます。Gofile がこのアプリのサーバーからのゲスト登録を断るときは、画面の「🔑 Gofile の設定」に Gofile の無料アカウントの「Account Token」を入れると読めます（その端末にだけ保存。サーバーの環境変数 `GOFILE_TOKEN` に入れても可）

ローカルのテストサイトを読みたいときだけ `THUMBS_ALLOW_PRIVATE=1 npm run dev` で起動します（本番では設定しないこと）。

### 既知の制限

- ブラウザで開くときは 1 ページ数秒〜十数秒かかります。無限スクロールは下まで最大 8 回スクロールした分だけ取れます
- YouTube などの埋め込み動画は再生のみで、保存はできません。HLS（`.m3u8`）配信の動画も保存できず、再生は Safari のみ対応です
- ログインが必要なページは読めません
- 大きな動画のダウンロードは、Vercel の関数の実行時間・転送量の制限に当たることがあります
- 別のサイトも辿る設定で階層を深くすると、ページ数がすぐ上限に達します（浅い階層から順に読みます）
